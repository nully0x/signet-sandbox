Your own signet.
One call.

Signet Sandbox provisions an isolated Bitcoin chain per team. Bitcoind in signet mode, a custom BIP325 block signer, and the services your application needs. Every call returns a connection bundle. A TTL deletes the environment when time is up.

Install

01 / CLI

One binary named signet, installed from a package registry. No repository clone.

$ cargo install signet-sandbox
$ npm install -g signet-sandbox

COMING SOON Neither package is published yet. Both commands activate at the first CLI release.

  • Docker daemon, running: Docker Desktop, colima, or OrbStack
  • Nothing else. Kubernetes stays internal, and you never run kubectl

First environment

02 / FOUR STEPS
  1. 01
    Bootstrap the local stack

    Creates the cluster, imports the images, starts the API, and writes a local identity.

    $ signet bootstrap
  2. 02
    Provision

    Waits until the environment is ready. The first run premines 101 blocks.

    $ signet up --name my-app --ttl 2h
  3. 03
    Read the bundle

    One object holds every endpoint plus the credentials that open it.

    $ signet get my-app --json
  4. 04
    Fund and tear down

    Fund any address from the faucet. Remove the namespace and the chain when the work is done.

    $ signet fund my-app tb1qexampleaddress --amount 100000
$ signet down my-app

THE BUNDLE

Configuration in. Credentials out.

Names resolve on the server, so scripts never track UUIDs. Disabled components are omitted from the object, not returned as null. Lightning entries are keyed by the instance name you chose.

WHAT AN ENVIRONMENT CONTAINS

Pick the parts you need.

The chain backend always comes up. Everything else is a choice you make at create time, and the choice is recorded in the bundle.

Components, their role, and whether they are always present or optional
Component Role When present
bitcoind Bitcoin Core in signet mode, one chain per environment ALWAYS
block signer BIP325 signer with a per-environment key, 30 second blocks or on demand ALWAYS
electrs Electrum indexer for wallets that track on-chain state OPT-IN
explorer Browser view of blocks, transactions, and addresses OPT-IN
faucet Funds any address with worthless coin from that chain OPT-IN
LND Named Lightning instances, one or many, with REST and gRPC OPT-IN

Lightning instances peer automatically after create. Channels stay manual, because channel liquidity is the thing under test.

WHY THIS EXISTS

Three bad options. One that fits.

01 / REGTEST

Too small

One node. No real peering, no real mempool behaviour, and no sync worth measuring.

02 / PUBLIC TESTNET

Too crowded

Shared with everyone, unreliable under load, and short of coins when you need them.

03 / MAINNET

Too expensive

Real funds and real risk during integration tests. One mistake costs money.

04 / THIS

Private signet

Real proof of work and real chain sync, on a chain that only your key can validate.

ISOLATED BY DEFAULT

One namespace.
One challenge.

Every environment gets its own Kubernetes namespace and its own signet challenge. Two environments cannot join the same chain, and there is no shared tier to compromise. A per-environment key signs every block. Destroying the environment deletes the namespace and everything inside it.

Local mode and hosted mode differ in connection details only, never in what the caller must know. The same configuration file that created a persistent environment works in CI with a TTL appended.

  1. { }
    01 / CONFIGURATION One schema, three surfaces

    CLI flags, a JSON file, or a direct RPC call produce the same validated object.

  2. →
    02 / PROVISIONING API JSON-RPC over one route

    NIP-98 signed events or an API token authenticate the caller. Failures are error objects, not HTTP status codes.

  3. ▦
    03 / ORCHESTRATOR Namespace per environment

    kube-rs applies the manifests. The signer, node, and services land in the namespace together.

  4. ↗
    04 / YOUR APPLICATION Connect and test

    The bundle carries endpoints, a macaroon, and the TLS certificate to pin. The reaper removes the rest.
